# 金額・月末予測・運用資産の表示

> この文書は開発段階ごとの計画・判断を整理したものです。状態と検証結果はその範囲に限ります。後続の変更と現行仕様は[ロードマップ](../roadmap.md)を参照してください。

## Context

確定請求、予測支出、安全余裕、最低確保額を二重計上せず、lock済みTDと模擬運用資産も重ねない必要がある。

## Decision

金額はAPI/DBでは通貨付き整数文字列、計算はbigint。運用可能額はmin(1回上限, max(0, TD残高 − max(最低確保額, 未払請求＋重複除外済み予測＋安全余裕)))。

月末はAsia/Tokyoのデモ時計で判定。recipient/recurrenceKey/対象月を基に、確定請求・支払済みと予測を照合する。予測入金を当てにしない。USDC最小単位はfloor(JPY×1,000,000/160)。銀行が最新データで再計算する。

未lock TDと模擬運用を表示し、lockは対応記録に分離する。USDC受渡し前は処理中と表示する。stub利息0・APY未取得。手数料0と固定レートを明示する。

## Alternatives

JS浮動小数点は最小単位の判定に不向き。最低確保額と安全余裕を無条件加算すると必要以上の二重確保になる。月末の将来残高だけで今すぐ運用すると途中の支払資金を失う。

## Consequences

合意した100万→20万支払い→40万残高＋40万運用を再現できる。曖昧な予測は実行せず要確認とする。実利回りや将来支払能力を保証しない。
